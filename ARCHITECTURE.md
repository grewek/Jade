## Project state

Workspace with two crates:

### `crates/core` (`jade-core`)

UI-independent library, zero external runtime dependencies (std only); `tempfile` is a dev-dependency only, for test-only temp vaults.

- `note.rs`: `Note` — one loaded Markdown file (`id` = relative path without extension, `title` = file stem, raw `content`).
- `links.rs`: `extract_wikilinks` — hand-written parser for `[[Target]]`, `[[Target|Alias]]`, `[[Target#Heading|Alias]]`.
- `vault.rs`: `Vault` — recursively scans a root folder for `.md` files into `notes: HashMap<id, Note>`, and every directory into `folders: HashSet<id>` (ids are `/`-separated relative paths, shared convention with note ids). `backlinks()` builds a target-id → source-ids map by resolving each note's wikilinks (match by id, else case-insensitive title via a `title_index()` built once per call); `search()` does a naive substring match over title/content. Reads a private `wikilinks: HashMap<id, Vec<WikiLink>>` cache instead of re-running `extract_wikilinks` on every call, kept in sync incrementally at every mutation point. `Vault::empty(root)` builds a notes/folders/cache-free vault (e.g. `jade-app`'s fallback when `Vault::open` fails). Still O(total links in the vault) per `backlinks()` call (every call rebuilds the whole map from scratch) — see Backlog.
  - `Note::save()` writes `content` back to `path`. `Vault::create_note(title, parent)` / `create_folder(name, parent)` dedupe within the target folder (" 1", " 2", ...). `update_note_content(id, content)` updates in-memory and persists. `rename_note(id, new_title)` renames in place, dedupes against existing titles, returns the new id. `delete_note(id)` removes the file and in-memory entry. `note::relative_id` strips the extension (notes); `note::relative_path_id` doesn't (folders) — both `/`-separated regardless of platform. `rename_folder(id, new_name)` moves via a single `std::fs::rename` then rebuilds the moved subtree's in-memory entries; dedupes against sibling folder names. `delete_folder(id)` is the recursive counterpart (`std::fs::remove_dir_all` + dropping every entry under that id prefix).
  - No Markdown rendering yet (needs a real parser crate like `pulldown-cmark`, added only after explicit approval).
  - Tests (`vault.rs`) use `tempfile::tempdir()` for a real-but-disposable vault directory per test — the `TempDir` guard cleans up on `Drop` even on a mid-test panic. Same pattern in `jade-app`'s headless UI tests.

### `crates/app` (`jade-app`)

Binary crate, depends on `jade-core` via path dependency and on `gpui-kit = "0.7"` (re-exports `gpui-component` as `gpui_kit::component`).

- `text_editor/` — Jade's own text editor, built directly on raw GPUI (`gpui-pre`/`gpui-base` primitives: `canvas()`, `window.text_system().shape_line(...)`, `window.on_mouse_event`, `EntityInputHandler`), **not** `gpui-component`'s `Textarea`/`Editor` (see HISTORY.md for why forking was rejected). Phase 1 (plain-text editing) is done; Phase 2 (Live Preview rendering) has landed through callouts and tables — see below and the Backlog for what's narrower than full CommonMark.
  - `buffer.rs`: `EditorBuffer` — a pure, GPUI-free `String` + `cursor`/`anchor` (selection) model, exhaustively unit-tested without window/entity machinery. Cursor movement is char-boundary-based, not grapheme-cluster-based. Sticky `preferred_column` makes `move_up`/`move_down` behave like a real editor. `insert`/`delete_range` snapshot onto a linear `undo_stack`/`redo_stack` (one entry per mutating call, no coalescing).
  - `live_preview.rs`: Phase 2's *inline* rendering model — pure, GPUI-free, exhaustively unit-tested. `build_display_line(line, active) -> DisplayLine` hand-scans one line for headings/bold/italic/inline-code/strikethrough/wikilinks/blockquote-`>`-prefixes/list-markers, hiding their markup to zero display width and tagging visible text with an `InlineStyle`. List markers are the one exception to "hidden means gone": their raw `-`/`1.` is *replaced* with a bullet (`•`) or canonical `N. ` — `DisplaySegment::is_replaced()`, orthogonal to `is_hidden()`. `DisplayLine` carries `display_text` plus `segments: Vec<DisplaySegment>` for raw↔display byte mapping (`display_offset_for_raw`/`raw_offset_for_display`). The active line (containing the cursor) always renders raw/unstyled. Emphasis matching is simplified (`**x**`/`__x__` is bold, a lone `*x*`/`_x_` is italic) rather than full CommonMark flanking-delimiter resolution. `compound_inner` handles one level of compounding (`> # Heading`, `- # Heading`, `- > quoted`, `> - item`) — never two levels deep, never list-in-list on one line. Also exposes `hidden_line(line)` for a fence delimiter or thematic break.
    - Also supports: backslash escapes, HTML entity references (common named subset + full numeric), thematic breaks (rendered as a vector rule), inline links `[text](url)` (a leading `!` suppresses the match — images are deferred, no bitmap-paint pipeline exists), bracketed/bare autolinks (lowercase scheme only for bare URLs), and GFM task-list checkboxes (render-only, no click-to-toggle). An unordered marker's bullet + checkbox collapse into one glyph (`"- [ ] x"` → `"☐ x"`); an ordered marker keeps its number (`"1. [ ] x"` → `"1. ☐ x"`).
    - Permanently declined (not just deferred): setext headings, 4-space indented code blocks, link reference definitions (`[text][ref]`/`[foo]: url`), raw inline/block HTML.
  - `classify_block_context(source) -> Vec<LineContext>` resolves nested-list depth and lazy continuation — the one thing needing cross-line state besides fenced code/tables/callouts. Each line is `LineContext::Plain`, `ListMarkerLine(depth)` (via an indentation-column stack), or `LazyContinuation(LineIndent)`. A blank line or heading always closes whatever was open. `build_display_line_in_context` applies it. Lazy continuation is deliberately more lenient than CommonMark: a continuation line stays part of the open list/blockquote regardless of its own indentation.
  - `element.rs`'s `indent_px(level) -> Pixels` (also used by `input_handler.rs`) converts `LineIndent::level()` into a pixel shift via `INDENT_UNIT`, applied consistently in `paint_lines`, `offset_for_position`, and `bounds_for_range`. A blockquote additionally gets a left "quote bar" (`QUOTE_BAR_WIDTH`, `MUTED_COLOR`) per nesting level. `shape_display_line` force-resets `LineIndent` to `None` for fenced code content.
  - `block_preview.rs`: fenced code (`` ``` ``/`~~~`) — the only thing that can't be classified one line at a time. `LineRole` (`Plain`/`FenceDelimiter`/`FenceContent`) + `classify_lines(source) -> Vec<LineRole>`, a hand-written sequential pass tracking fence open/close state. Computed once per paint since it needs the whole document.
  - `table_preview.rs`: tables — independent of fence-tracking and `classify_block_context`. `scan_row(line) -> Row` splits a `|`-delimited row into `Cell`s (raw byte range + trimmed/unescaped text). `classify_tables(source) -> (Vec<Option<usize>>, Vec<Table>)` is a whole-document sequential pass: a pipe-row + valid delimiter row (cell count must exactly match the header's) starts a `Table`, continuing through pipe-rows until a blank line, non-pipe line, or EOF. `Table` carries `start_line`/`end_line`/`byte_range`/`columns: Vec<Column>` (`width` = widest cell's character count, `align` from the delimiter). `pad`/`pad_amounts` align a cell to its column's width.
    - Rendered as an actually-aligned grid (tractable since the editor's font is always monospace) — `build_table_row` pads cells and leaves blank gaps where grid lines go; `element.rs`'s `paint_lines` paints the outer box/column dividers/header rule as real vector quads over those gaps (`column_divider_char_offsets`, `mono_char_width`), not box-drawing glyphs (see HISTORY.md for why glyphs didn't work). `push_cell_content` keeps cell text a byte-exact click target except when a cell contains an escaped pipe (falls back to one collapsing segment).
    - **Whole-table-active policy**: the cursor anywhere in `Table::byte_range` renders the entire table raw (`element.rs`'s `is_table_active`) — a table's alignment can't be resolved from one row in isolation, unlike every other construct's single "active line."
    - A too-wide table never overflows the pane: `cap_column_widths` proportionally shrinks columns to a character budget (never below `MIN_COLUMN_WIDTH`), then `wrap_cell_text` word-wraps any cell that still doesn't fit. `resolve_widths`/`table_row_char_budget` are the shared entry points so rendering and grid-line geometry never disagree. A wrapped row's cells fall back to a coarser (non-byte-exact) click target.
    - Tables don't nest inside blockquotes/lists, and a table-like pipe sequence inside fenced code is never mistaken for a real one, and cell content is never inline-scanned (no bold/code inside a cell).
  - `callout.rs`: Obsidian-style callouts (`> [!info]` etc.) — the other construct needing cross-line state (telling a header line apart from a continuing body line). `classify_callouts(source) -> (Vec<Option<usize>>, Vec<Callout>)` tracks whether the previous line was part of an open blockquote and which `Callout`, if any, it belongs to. A line opens one when it's a fresh depth-1 blockquote line matching `callout_header_prefix` (`[!type]` + optional `+`/`-` fold marker + optional title). `resolve_callout_type` maps the raw, case-insensitive type name to one of 13 `CalloutType` groups via Obsidian's alias list, defaulting to `Note` for anything unrecognized. **Top-level only** — a `>>`-nested line is never checked as a potential header. `callout_icon(kind) -> &'static str` gives one glyph per group. Render-only: the fold marker is parsed/hidden but every callout always renders fully expanded regardless of it — see Backlog.
    - `live_preview::build_callout_header_line(line, active)` renders a header line: raw if active; otherwise hides `> [!type]+/-`, then either inline-scans a custom title (styled `InlineStyle::CalloutTitle`) or shows the capitalized raw type name, with the icon glyph prepended.
    - `element.rs` integration: `callout_at_line` resolves a line's `Option<&Callout>`. `InlineStyle::CalloutTitle` is bold + `callout_color(kind)`; a callout's body `Blockquote`/`ListMarker` runs use the ambient text color instead of `MUTED_COLOR`. Background tint + accent bar are painted as vector quads in a pre-pass *before* the per-line text loop (so text paints on top), using `(top, bottom)` pixel ranges recorded by `measure_document`. The ordinary per-line quote-bar is skipped for any line belonging to a callout.
  - `element.rs`: `render_editor` composes a plain `div()` (sizing, focus, `on_key_down`) with a `canvas()` for text/cursor/selection painting and mouse hit-testing, rather than hand-implementing `gpui::Element`. Registers `window.on_mouse_event` listeners fresh every paint. Paints with `Theme::global(cx).mono_font_family`. `is_active_line`/`shape_display_line` (`pub(super)`, also used by `input_handler.rs`) determine per-line active state and shape Live Preview display text into a multi-run `ShapedLine`/`WrappedLine` (font/color per `InlineStyle` — `MUTED_COLOR`/`CODE_COLOR`/`WIKILINK_COLOR`/`LINK_COLOR`/`callout_color(kind)`, all flat hardcoded `Hsla`, not yet theme-driven — see Backlog). `paint_lines`/`offset_for_position` route raw↔pixel conversion through `DisplayLine::display_offset_for_raw`/`raw_offset_for_display`.
  - **Soft line-wrapping**: `shape_display_line` calls `shape_text(..., wrap_width, None)`, returning a `WrappedLine` that can span multiple visual rows per raw line. `wrap_width_for` picks the width (`None` = never wrap, for a table row/rule specifically, to preserve column alignment — a too-wide table is instead handled by `table_preview.rs`'s own capping/wrapping). `paint_lines`/`offset_for_position`/`bounds_for_range` track a running accumulated Y offset and use `WrappedLineLayout`'s 2D hit-testing. `measure_document` computes total height via `LineLayout` before the paint closure runs, using `editor.scroll_handle.bounds().size.width` as the width estimate, falling back to `Pixels::MAX` when that's zero (before any tracked ancestor has laid out).
  - **Viewport-bounded rendering**: `measure_document`/`paint_lines`/`offset_for_position` only shape lines actually on screen. `LineLayout` (built by `analyze_line_layout`) wraps `DocumentCache`/`RowHeightCache` (see below) rather than a flat per-paint array — every query (`line_range`/`cumulative_at`/`height`) is an O(log n) lookup into one of those two persistent caches. `visible_line_range` binary-searches `cumulative_at` (`partition_point_cumulative`, matching `[Pixels]::partition_point`'s own semantics) against the viewport's current Y-range (+ `OVERSCAN_LINES` padding) to find which lines to actually shape. Cut a 320K-line stress-fixture render from ~10.1s to ~1.4s.
  - **Row-height caching** (`RowHeightCache`, in `element.rs`): persists every line's estimated wrapped-row count (via `wrapped_row_count`) across paints in a `Fenwick` tree, closing the gap viewport-bounded rendering left open — `analyze_line_layout` used to call `build_display_lines` for *every* line on *every* paint just to estimate row counts, confirmed by direct measurement to cost ~140-155ms per keystroke on the 320K-line fixture even after classification itself (`DocumentCache`, below) dropped to sub-1ms. Three invalidation triggers: an edit (`Editor::record_edit`/`invalidate_all` patch `RowHeightCache` synchronously, right after `DocumentCache`, using the touched-line range `DocumentCache::record_edit` now returns, and the render parameters `element::render_params` computes — the same font/width/color `render_editor` itself uses, factored out once a second call site needed it); a cursor move with no edit (`RowHeightCache::sync_active_line`, called lazily from `analyze_line_layout` every paint — cheap, since it only ever patches the old and new active line); a render-context change, i.e. resize/font (`RowHeightCache::needs_full_rebuild`'s `available_width`/monospace-`char_width` fingerprint, also checked in `analyze_line_layout`, triggering a full `rebuild` — the same O(document) cost `analyze_line_layout` used to pay on *every* paint, now only on an actual resize/font change or the very first paint after opening a note). Validated against a full-rebuild oracle via randomized property tests (`element.rs`'s own test module), the same discipline `document_cache.rs`'s tests already use. **Measured**: a single keystroke's render cost on the 320K-line fixture dropped from ~140-155ms to ~13-16ms — close to the 16.66ms/60fps bar, though the edit side of a single keystroke (buffer mutation + GPUI's own keystroke-dispatch overhead, confirmed by direct measurement to be outside this cache's and this codebase's own code — see HISTORY.md) still adds another ~15-20ms on top, so a full edit+render cycle isn't under budget yet.
  - **Incremental classification caching** (`document_cache.rs`, `fenwick.rs`): `DocumentCache` lives on `Editor` behind `Rc<RefCell<_>>`. Every mutating call site in `editor.rs`/`input_handler.rs` reports a `TextEdit {start_byte, old_end_byte, new_end_byte}` to `Editor::record_edit`, which patches the cache before `notify_changed`; undo/redo go through `Editor::invalidate_all` (full recompute). `fenwick::Fenwick` (O(log n) point-update/prefix-sum over per-line byte strides) maps an edit's byte offset to a line index without a full rescan. `block_preview`/`callout`/`live_preview::classify_block_context` are resumable state machines — their patch functions resume from the edited line's cached state and walk forward until reconvergence with a later cached state. `table_preview::classify_tables` isn't per-line (column widths are an aggregate over the row range) — `patch_tables` rescans a bounded window (edited range + any table an edited line belonged to + the surrounding contiguous pipe-row run) and splices against kept prefix/suffix tables. Any edit with a nonzero net line-count delta falls back to a full recompute (the Fenwick tree is fixed-size). `record_edit` returns the union of every classifier's own touched-line range (`Some(range)`, or `None` on a full recompute) — not used by anything in this module itself, but what `RowHeightCache` (above) consumes to know exactly which lines' row counts need re-deriving after an edit, instead of the whole document's. All four were validated against their own whole-document function as an oracle via randomized property tests. **Measured**: all four combined cost well under 1ms per edit even on the 320K-line fixture — classification is no longer the bottleneck (see the row-height caching bullet above for what was next, and the Backlog for what still is).
  - `input_handler.rs`: `impl EntityInputHandler for Editor` — GPUI's platform text-input/IME layer (UTF-16 offsets; `utf16_to_utf8`/`utf8_to_utf16` helpers at the boundary). `character_index_for_point` returns `None`. `bounds_for_range` reuses `element.rs`'s layout/shaping helpers so IME positioning agrees with what's painted.
  - `editor.rs`: `Editor` — the entity owning one `EditorBuffer` + `FocusHandle`. `handle_key_down` handles navigation, editing (Backspace/Delete/Enter), and clipboard Ctrl/Cmd shortcuts explicitly; plain typing goes through `EntityInputHandler::replace_text_in_range`. `EditorEvent::Changed` fires only when the buffer's text actually changes, not on cursor/selection-only changes. Tab is handled via a dedicated `InsertTab` action bound in a `"TextEditor"` key context on the editor's own div (outranks `gpui_kit`'s global `"tab"` → focus-next binding) — any off-screen test window opening an `Editor` must register this binding itself.
  - `scroll_handle: ScrollHandle` is owned per-`Editor`. `autoscroll_to_cursor` (in `render_editor`'s paint closure) scrolls the cursor's line into view while focused, gated by `last_autoscrolled_cursor: Rc<Cell<Option<usize>>>` so a manual scroll away from the cursor isn't snapped back on every repaint — only re-triggers on an actual cursor-offset change.
  - Headless tests for `text_editor` use the same `gpui-kit` `test-support` harness as `main.rs`'s (see below).
- `main.rs`: takes an optional vault path as the first CLI arg (defaults to `./vault`), opens it via `jade_core::Vault::open`, renders a `JadeApp` view (implements `Render`).
  - `vault/Markdown Showcase.md` is a living *local* fixture — `vault/` is gitignored, so recreate it locally if missing. Demonstrates every Live Preview construct currently supported, and deliberately omits ones that aren't. **Update it in the same change that adds or changes a Live Preview rendering construct.**
  - Left sidebar: two tabs (`JadeApp::sidebar_tab`: `Vault`/`Search`) via plain styled divs, not `gpui-kit`'s `TabBar` (no `.test_support()` support, no need for its extra machinery). The `"NoteList"` key context (F2/Backspace) wraps only the Vault tab's tree, not the Search tab's `Input`.
  - **Vault tab**: "New note"/"New folder" buttons above a recursive collapsible folder tree (`render_tree_level`/`render_folder_row`/`render_note_row`), subfolders before notes, both alphabetical. Folder rows are `"folder-{id}"` (prefixed to avoid an `ElementId` collision with a same-named note). Collapse state in `collapsed_folders: HashSet<String>`. Right-click opens "New note"/"New folder" scoped to that folder.
  - **Search tab**: single-line `Input` (`search_input`), live-filters via `Vault::search()` on `InputEvent::Change`. Results keyed `"search-result-{id}"` (namespaced to avoid a sidebar-tree id collision).
  - **Right pane**: one continuous `text_editor::Editor` entity per open note (`JadeApp::editor`), not per-block widgets. Below it, a "Backlinks (n)" panel via `Vault::backlinks()`, keyed `"backlink-{note_id}"` (avoids a sidebar-id collision).
  - **Autosave**: `open_note` subscribes to `EditorEvent::Changed`; `autosave_editor` persists via `Vault::update_note_content` and re-notifies.
  - `flush_editor` (called before `open_note`/`rename_note`/`rename_folder`) persists and drops the current editor — kept as a cheap defensive measure even though `EditorEvent::Changed` is now synchronous.
  - "New note"/"New folder" call `Vault::create_note`/`create_folder` (root or scoped folder) then open the result.
  - **Rename/delete**: only via right-click context menu or hotkey (F2/Backspace), not sidebar buttons. `open_rename_dialog`/`open_delete_dialog` take the target id/title + `Entity<JadeApp>` + `window`/`cx` explicitly (context-menu callbacks don't get a `Context<JadeApp>`). Folders have the same via context menu only (no hotkey — no "selected folder" concept); `open_rename_folder_dialog`/`open_delete_folder_dialog` mirror the note versions with distinct element ids. `rename_folder`/`delete_folder` both `flush_editor` first, then reconcile `collapsed_folders` and the open editor against the folder's old id prefix.
  - Hotkeys are scoped to the `"NoteList"` key context, active only while `JadeApp::sidebar_focus` is focused (`.track_focus(...).key_context("NoteList")`, re-focused on every note click).
  - **Command palette** (`Ctrl+P`, global): bound via `KeyBinding::new("ctrl-p", OpenCommandPalette, None)` + `cx.on_action::<OpenCommandPalette>(...)` — a genuinely global handler, not `.on_action` on an element (action dispatch only walks the path from the *focused* node, which can be empty; see HISTORY.md). Hosts `gpui_component::command::Command` inside a plain `Dialog`. `CommandState` must be focused explicitly (`state.focus(window, cx)`) or Enter/arrows have nothing to dispatch to. Currently one item ("Open Settings").
  - **Settings dialog** (`open_settings_dialog`) is a non-functional placeholder (`.id("settings-panel")`) — see Backlog.
  - **Icon assets** require `.with_assets(gpui_kit::assets::Assets)` in `main()`'s `gpui_kit::application()` builder, or every `IconName` renders empty.
  - A raw `window.on_mouse_event` listener (the editor's own click/drag-select) isn't hitbox-aware — it doesn't know a `Dialog`'s backdrop occludes it. Mouse-Down/Move listeners must bail out via `window.has_active_dialog(cx)` (`MouseUp`'s reset stays unconditional) — see HISTORY.md for the stuck-selection bug this fixed.
  - Rename and "New folder" dialogs: a plain `Dialog` + `Input` + custom `DialogFooter`, with `.on_ok(...)` set to the same commit logic as the footer button (required — `on_ok` is what Enter actually dispatches to). Delete uses `AlertDialog` (`.confirm().ok_variant(ButtonVariant::Danger)`), whose default footer already wires `on_ok`; its default buttons have fixed ids `"ok"`/`"cancel"`.
  - Tree-row indentation uses `.ml(px(depth * N))` (margin), not `.pl(...)` (padding doesn't move a box).
  - To update a different entity from inside a dialog callback: capture `window: &mut Window` and call `entity.update(cx, |state, cx| state.method(window, cx))` — not `Entity::update_in`, which needs a `VisualContext` a plain `&mut Window` doesn't implement.
  - **Headless UI tests** (`main.rs`'s `#[cfg(test)]`, run via `cargo test -p jade-app -- --test-threads=1`): use `gpui-kit`'s `test-support` feature to render `JadeApp` off-screen and drive it with real hit-testing (`click`/`press`/`input`/`right_click` by element id) — prefer this over `ydotool`-driven manual testing. Any interactive element a test clicks needs `.test_support()` in addition to `.id(...)` (required for `try_find`/`find` too, not just `.click()`). Opening an overlay (dialog/context menu) is async even in tests — call `cx.run_until_parked()` between triggering it and interacting with it, across separate `cx.update_window(...)` calls. Import gpui-kit items explicitly, not `use gpui_kit::*`/`use super::*` (that glob also pulls in GPUI's `test` macro, shadowing `#[test]`). Each test's vault lives in a `tempfile::tempdir()` guard. Must run single-threaded — see `CLAUDE.md`'s Commands section for the rule and HISTORY.md for why. A `None`-context `KeyBinding` still needs *some* focused element to dispatch from — clicking a plain, non-`.track_focus()`-ed div doesn't establish focus. `gpui_component::command::CommandState` doesn't focus itself on mount either.
  - **Fonts**: `crates/app/assets/fonts/` bundles IBM Plex Sans (UI) and IBM Plex Mono (editor) under OFL 1.1. `main.rs`'s `install_fonts(cx)` embeds them via `include_bytes!` and sets `Theme::global_mut(cx).font_family`/`.mono_font_family`. Must be embedded (not system-installed) since users won't already have IBM Plex.

## Backlog

Deliberately deferred follow-ups — don't pick these up without checking in first (see `CLAUDE.md`), they're parked on purpose:

- **`Vault::backlinks()` still rebuilds its whole target→sources map from scratch on every call** (O(total links in the vault), not O(1)). A further step would maintain that map incrementally. Not done — even the worst-case measured cost (16.9ms on a 200-note × 20k-word synthetic vault) is comfortably under the ~100ms perceptible-lag threshold.
- **Live Preview Phase 2** — deferred: full CommonMark emphasis resolution (current matching is a simplified pairing, not the real flanking-delimiter algorithm); keeping formatting visible on the active line (it currently renders fully raw/unstyled); heading size (bold-weight only, since `shape_line` takes one font size per line); theme-driven colors (currently flat hardcoded `Hsla` constants in `element.rs`).
- **Markdown spec gap-fill** — permanently declined, not parked: images (no bitmap-paint pipeline exists), setext headings/4-space indented code/link reference definitions/raw HTML (philosophy + redundant with existing constructs), hard vs. soft line breaks (not applicable — every source line is already its own row here).
- **True WYSIWYG table editing** — hiding a table's raw pipe syntax entirely and editing rendered cells directly. No design work done yet.
- **Callouts**: fold/collapse interactivity (every callout always renders fully expanded regardless of the `+`/`-` marker — waits for a later dedicated "interactions" phase, along with task-checkbox toggling and WYSIWYG tables); nested callouts (one-level compounding cap, consistent with the rest of the editor).
- **Per-paint line-height/display-building caching landed** (`RowHeightCache`, see `element.rs`'s own bullet above) — the render side of a single keystroke on the 320K-line stress fixture dropped from ~140-155ms to ~13-16ms.
- **A single keystroke's *edit* side still costs ~15-20ms on the 320K-line stress fixture, confirmed to be outside this codebase's own code** — direct instrumentation (temporary, removed after use) traced `Editor::record_edit`'s own work (classification patch + row-height patch) to ~1ms total, and `EntityInputHandler::replace_text_in_range`'s own buffer mutation to ~1.5-2.5ms, leaving the remaining ~15ms unaccounted for inside GPUI's own `dispatch_keystroke` path (the vendored gpui/gpui-base/gpui-component stack), not Jade's. Not investigated further — would need digging into vendored code, out of scope for this pass; flagged here rather than silently dropped.
