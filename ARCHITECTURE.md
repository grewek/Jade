# ARCHITECTURE.md

Non-obvious invariants, gotchas, and the Backlog. Not auto-loaded. The code is the source of truth for module structure — grep it.

## Invariants

- **Live Preview**: the cursor's line renders raw. A table stays a rendered box with the caret in it: only the cell under the caret shows its raw text (see Table cell editing), and a table is raw as a whole (`is_table_active`) only on its delimiter row or after Ctrl+/. Callouts fold by click (see Interactions). List markers are *replaced* (`•`, `N. `), not just hidden. Lazy continuation is deliberately more lenient than CommonMark.
- **Cold build**: `DocumentCache::recompute_all` scans for newlines once (`line_strides`: SSE2 on x86_64, a word-at-a-time fallback elsewhere, no `memchr` per line, no pre-count) and the four passes read their lines back out of the strides, which then become the `line_index` Fenwick tree. Blank lines are decided from the first byte (`preview::is_blank`), table cell widths are computed without building cell strings, and a pipe row's delimiter is checked before its header is scanned. 81ms to 26ms on the stress fixture.
- **Text ownership**: note text exists once. `jade_core::Note` holds only id/path/title; the vault keeps the wikilink index and reads text from disk on demand (`read_note`, `save_note(&str)`, `search`). While a note is open its only copy is the editor buffer (`open_note` reads straight into it; autosave/flush write from the buffer's `&str`). No `.clone()`/`.to_string()` of the text anywhere (STYLE.md rule 14). Search reads files, so `JadeApp` caches results and recomputes only when `search_stale` is set by a mutation; searching runs on a background thread (`refresh_search` snapshots with `Vault::search_targets`, spawns, and drops results from superseded generations); never call `Vault::search` from `render`. Search sees disk, so unsaved edits show up after the 500ms autosave. The vault-open scan extracts wikilinks line by line (`link_targets_from_file`; a link never spans a line), and stores each note's distinct link targets only (`Box<[Box<str>]>`; the stress note's 27K links have 1 target), so scan peak is tiny, not a whole-file buffer (was a 14MiB peak; guard: `opening_a_vault_does_not_buffer_a_whole_note`).
- **Tables** (render-only): a table is a box. `table/geometry.rs` lays a row out in characters (`layout_row`: each cell's wrapped lines as byte ranges of the source line, the same greedy fill `table::wrapped_line_count` counts; `column_left`/`text_left`/`box_width`; `offset_at` maps a click to a raw offset). A rendered row is empty display rows (`row_line_count` of them, the multi-entry path images use), so heights and scrolling are unchanged; `paint_table_boxes` draws header tint (role `table_header`), column dividers, row separators and the outline before any text from the row cache's heights, and `paint_table_row` draws each cell's lines (`build_cell_line`: inline markup, never a block) aligned in pixels, the header bold. Widths wrap-and-shrink (`resolve_widths`, `fits_unshrunk` skips tables that fit): when the natural widths exceed the editor, `cap_column_widths` water-fills, so narrow columns keep their width and only the wide ones share the rest equally (a growing cell takes space from columns with room before anything wraps). A cell's width and longest word count a drawn formula at its drawn width (`text_metrics`, #47; the classifier knows no macros, so a formula that needs one counts as its source). No column goes below its longest word (`Column::word`, #46) while the longest words of all columns fit together; when they do not, the longest words are shortened to a common length (`fill_above`), so a word breaks only in a table too narrow for its words (a float given a small share). Column widths and wrapping count raw characters, so a cell with hidden markup shows a little narrower than its column. The cursor anywhere in a table still renders all of it raw; a click lands on the nearest character of the cell under it. Horizontal scroll is a possible later styling choice, not planned. Cost on the stress fixture: a viewport of tables paints in 1.8-2.7ms the first time, under 0.5ms once shaped.
- **Row heights** (`text_editor/rows/`, driven only through `RowCache::update`, `invalidate`, `verify`, `correct_late`): `RowCache` seeds non-table lines with an allocation-free over-estimate (`estimate_row_count`) and makes the lines in view exact before anything is positioned: `verify` shapes every line of the window as it enters it, and an edit patch shapes the (up to 64) lines it touches, so a count in the visible window is the shaped one; only off-screen lines keep the estimate, so the total height settles while scrolling (guard: `element/height_agreement_tests.rs`, #24). Making the window exact can change the rows of lines *above* the first visible one, which moves everything below; `LineLayout::verify_anchored` (called in the paint closure before anything is placed) returns that shift and the closure subtracts it from the editor origin and the scroll offset, so the content stays under the reader (guard: `element/anchoring_tests.rs`). Measured on the 105 MB note, 100 steps of 100px toward the start: jumps of 26-156px in 3-7 steps before, 0 at 20M px and 2-6px at 45M/61M after (GPUI's `f32` scroll offset steps 4px there). The estimates are approximations of the off-screen rows only, and they assume a monospace font: they count characters against `RowFontMetrics::char_width` (measured from the font once per rebuild, with its ascent and descent; comparable, so a font or size change rebuilds the cache). A test bounds how far they may stray from shaping (`the_cold_estimate_stays_close_to_the_shaped_count`: no line off by more than a row plus an eighth, few lines off at all; the miss is the slack greedy word wrap leaves at a row's end). A formula inside emphasis, strikethrough or brackets is shown as written, so the estimate (`Nesting`) does not grow its rows. Still tied to the current font: `MONO_ADVANCE_EM` (a formula's reserved columns, cached in em), and table/column geometry on a character grid; both change when custom fonts arrive (#24). The cold rebuild (`pure_row_counts`) runs on up to 16 threads that take 4096-line chunks from a shared queue (a run of costly lines, such as the formulas of a math section, is shared out rather than landing on one thread) and write into one array; each chunk finds its own line starts by scanning for newlines (`chunk_starts`), so no per-line table is kept or built. A `$$` block shown as a formula is its first line's `rows` and nothing on the others, with no window (`row_count_for_line`). `verify` skips shaping a line the estimate puts in a row or less when it is plain ASCII with no `$` (it cannot be short); everything else in the window is shaped. Resize frame (layout bench, stress fixture): 7.7ms before #26, 6.2ms after; stress_math 12.7 to 9.4ms. Table rows always use the exact path. Validated against `exact_row_counts`. The first frame has no width yet (`render_params` falls back to `Pixels::MAX`, so every estimate is 1 row), and callout backgrounds are drawn before the lines from these heights; `LineLayout::verify_rows` therefore makes the visible window exact before the callout pass (guard: `first_paint_of_a_huge_note_needs_no_row_height_corrections`).
- **`DocumentCache` patching**: edits report a `TextEdit` to `Editor::record_edit`. A line-count change (Enter, joining lines, multi-line paste) resizes every per-line array and both Fenwick trees at one splice point (`resize_lines`, `Fenwick::resize`, `RowCache::resize_for`), shifts stored line numbers of later tables/callouts, then runs the usual resumable walks. Undo/redo patch too: `EditorBuffer::undo`/`redo` return the `TextEdit` they applied (an undo entry is a delta). `classify_tables` (whole-document, with a per-line lookup) is now test-only: the oracle for the streaming `classify_table_list` production uses. A drawn table's delimiter line has no row (`is_hidden_delimiter`, #48: the header is as tall as its cells; raw mode gives it its row back). A table's delimiter row needn't contain `|`, so `patch_tables` widens its window to fixpoint over adjacent tables and the header above. Validated by a randomized test (25 seeds) comparing every field, entering states included, against a freshly built cache.
- **Undo**: bursts of same-kind edits coalesce into one delta (`UndoEntry`: replaced range + removed text), so memory scales with edited text, not document size; stack capped at `UNDO_STACK_CAP` (100).
- **Tabs**: `JadeApp.tabs` + `active_tab`; each tab owns an `Editor` (cursor/scroll/undo survive switching), at most one tab per note (opening an open note switches to it). `open_note` = "Open" (replaces the active tab's note, or creates the first tab), `open_note_in_new_tab` appends. Autosave writes only `dirty` tabs (set by the delayed `Changed` event); `open_note`, vault renames and quit save *all* tabs unconditionally because `dirty` can lag a keystroke. Rename/delete go through `retarget_tabs`/`remove_tab`. Cost: ~33MB RSS per open stress-size note (3 tabs: 152 to 249MB); switching to one costs ~10ms over two frames (its row cache is rebuilt for the current width); the tab bar adds ~0.1ms per frame.
- **Status bar** (`status-bar` under the editor): word and character counts from `text_editor::doc_stats`, per-line `(words, chars)` patched with the same `EditPatch` as the caches (`Editor::record_edit`), totals kept as running sums. A word is a whitespace-separated token with a letter or digit (list markers, `---`, `|` don't count); characters are scalar values, spaces in, line breaks out. Cold count at note open: 8ms on the stress note (threaded over whole-line chunks above 1MB; 21ms single-threaded), 0.3ms on a 150KB note; per edit 0.17us (char) / 0.09ms (Enter); 8 bytes per line (~2.5MB on the stress note). The harness `app` query reports `words`/`chars`.
- **App module map** (`src/app/`): `mod.rs` holds `JadeApp`'s state, constructor, `Render` and `run`; `tabs.rs` (`Tabs`: the tab list and its active index, changed only through its methods; plus saving and link following), `search.rs` (`Search`: query, results, background search, `mark_stale`), `notes.rs` (create/rename/delete), `dialogs.rs` (modals, settings, palette), `sidebar.rs` (tree, search, backlinks, resize), `chrome.rs` (tab and status bars), `tests.rs`. The colour-literal guard in `theme/tests.rs` lists every UI file by path: add new UI files to it.
- **Editor module map** (`src/text_editor/`, refactor in progress on `refactor/architecture`): `table/` (`model` parse and widths, `geometry` cell boxes, `ops` structure edits, `handles` hit rectangles; cell editing stays in `editor/table_edit.rs` and painting in `element/table_paint.rs` because they need those modules' private state), `columns/` (`mod` region model and markers; `split` pixel geometry; `ops` text edits; `handles` hit rectangles; menu/drag in `editor/column_edit.rs`, painting in `element/region.rs`, for the same private-state reason as tables), `preview/` (the per-line display model: `line` types, `build` display-line builders, `inline` scanner, `context` list/quote nesting, `fence` code fences, `callout`; formerly `live_preview.rs`, `block_preview.rs`, `callout.rs`), `doc/` (`DocumentCache`: `mod` the per-line caches and getters, `edit` `TextEdit`/`EditSpan`/`EditPatch`, `patch` the incremental classifier patches, `view` `ViewState`: what the editor sets about how the text is shown (column width, raw region/table, editing cell, justify, image sizes), reached as `doc.view`; formerly `document_cache.rs`), `lines/` (text to lines, no Markdown: `line_strides`, newline `scan`, `fenwick`, `chunks`, `splice`), `image/` (embeds, sizes, decoded cache), `layout/` (`LineState`, display-line building, shaping, monospace row arithmetic), `rows/` (`RowCache`: `update`/`invalidate`/`verify`/`correct_late`; nothing else is public), `element.rs` + `element/{input,paint,render,widgets,table_paint,region,justify}.rs` (the frame: render, mouse, painting). Dependencies point one way: layout -> rows -> element -> editor.
- **Math** (`text_editor/math/`, #13; parser, layout and inline painting): `parse(src) -> Formula` turns the text between `$` delimiters into `Node`s (`ast.rs`), GPUI-free. Total: whatever does not parse stays a `Node::Error` holding its source (shown in an error colour later), never a panic; recursion goes through `parse_atom`, capped at `MAX_DEPTH`, and sources over `MAX_SOURCE` are not parsed. `lex.rs` skips whitespace/`%` comments and reads `\text{}` raw; `symbols.rs` holds the command tables as plain `match`es. ASCII `-`/`*` become the real minus/asterisk glyphs in the tree. Macros (`\newcommand`) are #14. Release parse cost: 2-5us per formula. **Layout** (`layout.rs`, `font.rs`, `alphabet.rs`): `layout(font, nodes, display) -> Layout` is TeXbook appendix G with the Latin Modern Math MATH constants read through `ttf-parser` (`MathFont::bundled()`, `None` if the font cannot be read, so a caller shows the source). Everything is in em, so one layout serves every font size: cache it per formula (key: source and display flag). A `Layout` is `width/ascent/descent` and `Item`s: `Glyph { id, x, y, size, error }` (font glyph id, baseline position with y down from the formula's baseline, `size` 1.0 or the script scale) and `Rule` (fraction bar, root overbar). Letters map to the Mathematical Alphanumeric block (`alphabet::styled`); atoms space by TeX's table (`SPACING`; conditional spaces are dropped in script styles; a Bin after nothing/Op/Rel/Open/Punct or before Rel/Close/Punct is an Ord); delimiters and roots take the smallest size variant that is tall enough (the largest if none: no glyph assembly yet). Built: symbols, scripts, limits, fractions and binomials, roots with index, `\left/\middle/\right`, big and named operators, text, fonts, spaces, style switches, and (`layout/`) accents, braces and bars (`marks.rs`: combining marks lifted by `accent_base_height`, attached at the font's top-accent point; wide ones stretched), `\overset`/`\underset` (the limits layout; the base's class, through braces), `\xrightarrow`, `\not`, `\boxed`, environments (`env.rs`: cells in a grid centred on the axis, row struts, `\hline` and `|` rules, fences sized like `\left`; `aligned` starts the cells after an `&` with an empty atom so a leading `=` is spaced), and extensible glyphs (`stretch.rs`: smallest size variant that fits, else the OpenType parts assembly, horizontal for marks and arrows, vertical for tall delimiters). `\\` outside an environment stacks centred lines (a `gathered`), `\big`..`\Bigg` (+`l/r/m`) are fixed-size delimiters, `\phantom`/`\hphantom`/`\vphantom`/`\smash` keep part of a box, `\hspace{n unit}`, `\mod`/`\pod`, `\label`/`\nonumber`/`\notag` draw nothing. What still fails to parse is listed in #18. Release cost (parse + layout): 18-60us per formula (a 6x6 matrix is the high end), font init 0.06ms. **Painting** (inline `$…$`; blocks below): `math::rendered_span(span)` (`cache.rs`) strips the delimiters, parses and lays out once and caches by source (two maps, inline/display, dropped whole past 2048 entries); it returns `None` for a source that does not parse cleanly or a missing font, and the caller then shows the source as typed. `preview::scan_inline_in` turns a good span into a replaced `InlineStyle::Math` segment (raw = the span with delimiters) whose display text is `columns` blank spaces, `ceil(width_em / MONO_ADVANCE_EM)` with `MONO_ADVANCE_EM = 0.6` (IBM Plex Mono), so the preview stays GPUI-free and wrapping, hit-testing and the caret treat it like any replaced text. `element/widgets.rs::paint_math` draws the cached items over those columns with `Window::paint_glyph` (font "Latin Modern Math", registered in `install_fonts`; GPUI glyph id = the font's glyph index) and `paint_quad` for rules (at least one device pixel thick, not one logical pixel: `bar_thickness`, #50), on the row's text baseline, in the text colour (error glyphs in `InlineColors::broken`). The caret line renders raw like every construct; table cells (`build_cell_line`, `scan_inline_in(.., false, ..)`) never get a drawn formula because they paint their own text. **Row height** (#15, #32): `layout::row_heights` gives each row of a line a whole multiple of the editor's row height (`math::rows_to_fit`: the smallest count that keeps the tallest drawn formula on that row, set on the text baseline GPUI centres in the row, inside it), so row counts stay integral. A row's formulas are found by the wrapped row of each segment's ends (`position_for_index`), the same test `paint_math` uses to skip a split formula. A shaped line's heights are decided in one place, `layout::entry_heights` (per entry an `EntryHeight`: `row`, `varied`, `height`) and `shaped_height` (total and rows), which the paint loop (`LineSlot::entry`), `caret_rect`, `hit_in_line` and `shaped_row_count_for_line` all read (#24; regions still shape their own, #23); `move_by_row` steps by the caret's own row height. Only rows with a tall formula grow (#32). GPUI lays a wrapped line out at one row height, so an `EntryHeight` is uniform (`row` for every row: the common case, and a line whose rows are all equally tall, which GPUI paints as before) or `varied` (units of `row` per wrapped row); everything that turns a GPUI y into a painted one then goes through `EntryHeight::place` (position and row height) or `layout_y`/`row_at` (painted y to the row GPUI knows): the text, painted row by row by `justify::paint` (`RowPaint { entry, stretch }`, which also stretches justified rows), widgets and `paint_math`, the selection quads, the caret (`caret_rect`, `caret_bounds`, `paint_line`) and `hit_in_line`. Aside flow pieces take their height from `shaped_height` too. Applied inside `::: columns`/aside regions too (#23: `shape_region`, `shape_at`, the caret in a column and the painted row height all read `entry_heights`/`shaped_height`, so a region is as tall as its lines; guard: `element/formula_context_tests.rs`, which also checks a paragraph, heading, lists, task, quotes and callout rows grow and that the cold estimate equals shaping in each; a table cell shows its source and stays one row). A formula the wrap splits across rows is not drawn (below). The cold estimate counts them (`estimate_row_count`: `inline_math_extent` reads each formula's reach with `math_scan::scan_inline`, the rows of the display characters plus, for each row with a formula, the extra rows its tallest one needs: `settle_formulas` moves a formula that would cross a row's end to the next row's start, as the wrap does, and the row of a formula is its character offset over the characters per row, so a word wrap that moves it further leaves the estimate a row or two off, which painting corrects; `state_row_count`, which edit patches use, does the same, and `verify` shapes every line with a `$`), so the height does not creep as a note scrolls (#20). The caret line draws raw, so a tall line shrinks while it is edited. A one-line `$$x$$` that is the whole line is centred in its row (`paint_math`, `WidgetPaint::row_width`). **Blocks** (multi-line `$$ … $$`): `DocumentCache::math_blocks` (`doc/math.rs`) holds each as `MathLines { first_line, last_line, rows }`, derived from `jade_core::math_scan::scan_blocks` and patched per edit like tables (`patch_math`: rescan a window from 256 lines above the edit, widened until it holds every block that starts before the line from which the old blocks are still right; checked against a fresh scan in the randomized edit test; a window with no `$$` in it is skipped with one search). The row cache measures a block (`rows/count.rs::measure_math_block`, before any of its lines is shaped: the cold rebuild sends every block line through the window path, `sync_active_line` re-measures all of a block's lines when the caret enters or leaves it) and stores `rows` (`math::block_rows`: formula height at `MATH_SCALE` plus half a row of air; `0` if the body does not parse) in the block. `LineState::math` is `Head(rows)` on the first line (`build_display_lines` gives it that many hidden rows; `paint_line` draws the formula centred over them with `widgets::paint_math_block`), `Tail` on the others (`hidden`, no rows, like a folded callout), `None` while the caret is in the block (all lines are plain source) or when it does not parse. A block inside a `::: columns`/aside column is a formula too (`LineState::in_column` keeps `math`, hides the `Tail`; the region's row counts call `measure_math_block` for each column line first), unless it runs across a divider (`block_in_one_column`), when it stays source. The link table, `find_heading_line` and image embeds skip block lines (`DocumentCache::in_math_block`); core's link targets, backlink contexts and rename skip them through `math_scan::BlockLines`/`prose_lines` (`link_targets_from_file` has a lookahead loop, entered only at the first line that may open a block). Arrow up from the line below a block lands on its first line (the block opens as source). Cost on the stress fixture with ~2900 blocks near the viewport: frames as without them (idle 0.68ms, keystroke+frame 1.96ms, scroll 0.87ms); opening 99ms vs 86ms; a sidebar-drag rebuild 12.9ms vs 7.9ms (every block measured); an edit inside a block allocates ~3KB. **Known gaps**: a formula wider than a row is shown as its source (`preview::show_wide_formulas`, called from `build_display_lines` with the row's character fit; the row estimate's `inline_math_extent` applies the same limit, #49), and in the corner where a formula that fits a row follows one short word with no earlier break point the wrap can still split it, leaving it blank; #18 lists commands not supported yet. A `\\` inside a group stacks lines there (`Typesetter::lines`, same as at the top level). `crates/app/benches/fixtures/math_showcase.md` is the hand-check note for all of it. Phase 3 (#18, in progress): `\color{c}` (`Node::ColorSwitch`, for the rest of its list) and `\textcolor{c}{x}` (`Node::Color`) set `Item::color` (`0xRRGGBB`; names and `#rgb`/`#rrggbb` only, no theme roles; an inner colour wins, an unknown one is source); `\tag{n}`/`\tag*{n}` becomes `Layout::tag` of a display formula (the last one counts, none inline), painted at the block's right edge by `paint_math_block`, which moves the formula left if they would meet. `\cancel`/`\bcancel`/`\xcancel` (`Node::Cancel`) add `Item::Line` strokes (painted with a `PathBuilder` stroke) corner to corner over the body, 0.1em past it, without changing its box. Also parsed: `\atop` (`FracKind::Atop`, a fraction with no bar), `\dddot`, `\widecheck`, `\overparen`, `\overleftrightarrow` (accents; the last three stretch), `\underbar` (= `\underline`), `\mathinner`, `\strut`/`\mathstrut` (a parenthesis-high zero-width phantom) and `\fbox{text}` (a framed `\text`). `\tiny`..`\Huge` (`Node::Size`: like `\color`, the rest of the group is laid out as a sub-list and `Layout::scale`d, MathJax's factors), `\above` (a bar unless the thickness is 0) and `\genfrac` (a `Frac`, in `Delimited` when it has delimiters). `\eqref`/`\ref` are #35.
- **Math macros** (#14, note-local; part of Math above): `math/macros.rs` reads `\newcommand`/`\renewcommand`/`\providecommand` (optional `[n]`, `[default]`), `\def\x#1#2{…}` and `\DeclareMathOperator[*]` into `Macros` (a `BTreeMap`; the last definition of a name wins for the whole note, not only after it) and `Macros::expand` cuts a formula's definitions out and replaces macro uses by their bodies as *text* before `parse`, so parser, layout and painter know nothing of macros (a use with too few arguments stays for the parser to flag; `\text{…}` bodies are not expanded; `MAX_EXPANSION_DEPTH` 32 and `MAX_SOURCE` end a runaway macro in `TooDeep`, shown as source). `DocumentCache::macros()` (`doc/macros.rs`) holds the table and `macro_lines`, the plain-text lines that mention a definition command. `recompute_all` finds them with one backslash pass (`definition_starts`, ~1ms on the 12MB stress fixture); `patch_macros` re-reads only the lines any classifier touched and rebuilds the table from the `$…$`/`$$` sources of the definition lines. A changed table (`Macros::stamp`) makes `record_edit` report the whole note touched, so every row count is re-derived; the formula cache stores the stamp with each entry. The table reaches the code that measures and paints through `LineState::macros`, `DocView::macros`, `WidgetPaint::macros` and the `macros` argument of `entry_heights`/`shaped_height`/`formula_reach`/`build_*_with`. A definition-only formula expands to nothing: one blank column inline, one blank row as a block.
- **Formulas in table cells** (#39): a rendered cell line is built by `build_cell_line_with` (inline formulas drawn, macros expanded) and falls back to its source when the drawn line would be wider than the column. Column natural widths are still the raw source widths (`classify` knows no macros), but wrapping is formula-aware (`table::model::chunks`): a drawn formula is one unbreakable run of its drawn width (`cell_formulas`, a formula wider than the column wraps as text), a word touching one is cut at its edges into glued runs, and `wrapped_line_count_in` and `wrap_ranges` both use those runs so counts and ranges agree. A column can therefore be wider than its drawn formulas need (#43 follow-up if that matters). A formula taller than a row makes every cell line of the row `row_scale` rows high (`table_row_scale` in `layout/shape.rs`; `table::row_scale` recovers it from the entry count for painting and hit-testing); the text sits in the middle of its slot. The cell being edited shows source and does not count. The cold estimate sends table rows containing a `$` to shaping, so their height is exact.
- **Math delimiters** (`jade_core::math_scan`, #13, the one definition of where math is; same shape as `link_scan`): `parse_inline(line, start, end)` is the leaf parser at a `$` (`$x$` and one-line `$$x$$`; Obsidian's rules: opener followed by non-space, closer preceded by non-space and not followed by a digit, `\$` escapes, the first `$` after the opener decides, so `$5 and $10` is text), `scan_inline` the code-span-aware walk, `opener_len` how far past a failed opener to move. `scan_blocks(text)` finds multi-line `$$` blocks (opener at line start, closer within `MAX_BLOCK_LINES`, no blank line or fence between: single line breaks are whitespace to LaTeX, a blank line ends the formula; an unclosed `$$` is plain so typing it never turns the rest of the note into math). `link_scan` and the preview's `scan_inline` treat inline math as opaque (no emphasis or links inside; the preview draws it, see Math) and the differential test covers `$`. Wired in: the document cache (`doc/math.rs`) and every line walk of links, backlinks, rename and context skip block lines like fenced code (see Math). Not wired: full-text search still searches inside formulas (like Obsidian); openers behind a blockquote or list marker are not found.
- **Settings** (`src/settings/`, #58; GPUI-free, pure): the resolved typography settings, `Typography` (all `Copy`: `font`, `shape`, heading arrays per level, one small struct per element). `Typography::default()` is today's look (16px text on a 26px row, plain headings, no boxes), guarded by `the_typography_default_matches_the_window_text_style`; each later step of #58 switches a key on where it implements it. Sizes are multiples of `font.size`; only radii, border and bar widths are px; `radius_of(Boxed)` is an element's own radius else `shape.radius`. Only IBM Plex Mono is a `FontFamily`. `Typography::from_config(src)` / `settings::load(dirs)` read `[font]`, `[shape]`, `[heading]` and the element tables (`[inline_code]`, `[code_block]`, `[callout]`, `[table]`, `[image]`, `[link]`, `[blockquote]`, `[list]`, `[task]`, `[spacing]`; `read/blocks.rs`) from `config.toml` (`theme::config_text` is the bounded file read): each key is judged alone, so a missing, mistyped or out-of-range value gives that key its default (numbers are clamped, e.g. size 8..40, scale 0.5..4) and one notice, never a panic; per-level arrays take 1 to 6 entries (the last repeats); another font family is refused; an element's `radius` is its own, else `shape.radius` (`"full"` allowed), enum keys are case-insensitive names, `list.bullet_shapes` is a short array like the heading ones; unknown keys in these tables are noticed, other tables and keys are ignored. `text_editor::TextSettings` is the global (`justify` plus the `Typography`), read at startup (`install`) and again on every config change (`reload`, called by the theme watcher through a callback so the theme module does not know it; justify follows the file now too): a layout key that moved (`Typography::layout_differs`; a new key counts as layout until listed as paint-only) bumps `settings::layout_generation`, which every `RowCache` compares with its own so all caches rebuild once at the next layout, while a paint-only change just repaints. - **Heading rows (#58 C1 spike, `element/heading_spike_tests.rs`)**: a heading is shaped at `font_size * scale` in one `shape_text` call (one size per call is enough, a heading is a whole line) and gets `EntryHeight { row: body_row * units, varied: [], height: rows * row }`, the shape a tall-formula line already has, so heights stay whole editor rows and nothing downstream (row counts, scroll anchoring, caret, hit test via `place`/`layout_y`) needs fractional rows. Measured: the mono advance (regular and bold) is exactly linear in size (ratio 1.0000 from 1x to 3x), so the cold estimate is the body estimate with `char_width * scale` and each wrapped row counting `units`; word wrap needs more rows than the character count for the same reason as body text (never fewer; the in-view verify corrects it). `wrapped.size(row).height == rows * row` exactly. The cost of whole rows is slack: a row of `ceil(scale)` body rows gives line-height 2.95 at scale 1.1 and 2.6 at 1.25, so use `units = max(1, round(scale))` (1.1 and 1.25 stay one row, 1.5 and 1.75 two, 2 two, 2.5 and 3 three; the text box is 0.75 em tall, so it always fits). A fractional row height would break the integer row counts the estimates, anchoring and `height_agreement_tests` rely on. Implemented (C2): `DisplayLine::font_scale()`/`row_units()` read `heading.scale` (atomics set with the global, `settings::heading_scale`/`heading_rows`); `shape_entry` shapes at the scaled size, `row_heights` takes `row_units()` as the base (a taller formula row still wins), `state_row_count` scales the character width and multiplies by the units; the cold estimate (`estimate_row_count`, C3) counts a plain `#` heading with `char_width * scale` and `units` per row (exact unless word wrap needs a row more; a heading in a quote/list item or with a `$` is still estimated at body size and corrected by the in-view verify, C6), and the default scales are 1 (no change). Weight and colour (C4): `heading.weight` (atomics, `settings::heading_weight`; paint-only, only Regular and Bold are bundled so GPUI picks the nearer) and the `heading_N` theme roles (`InlineColors::heading`, so a `[colors]` override works) are read by `font_for_style`/`color_for_style`; defaults (700, roles following text) look as before. Space and rule (C5): `heading.space_above`/`space_below` are rounded to whole body rows (`settings::heading_space_rows`; the row counts and scroll anchoring need integral rows, so 0.3 is 0 and 0.8 is 1) and become `EntryHeight::pad` (`height` includes both; `top`, `row_at`, `layout_y`, `place` and the plain text paint add `pad.0`, so the caret, hit test, selection and widgets follow); `estimate_row_count`/`state_row_count` add the rows, and `RowCache::verify` shapes any line with a `#` (a heading in a quote or list is not caught by the cold estimate). `heading.rule` (paint-only) draws a 1px `border_strong` line at the bottom of the text rows, above the space below. Contexts (C6): a heading in a quote or list item or a callout body scales like any other (`DisplayLine::heading_level`; the hidden `#` prefix segment carries `InlineStyle::Heading(level)`, so a heading made only of bold, a link, code or a formula is still one); a `#` in a callout title is title text and stays body size. A formula in a heading is drawn at `font_size * scale` (`paint_math`), counts its rows at that size (`row_heights`: `tall_rows` against the heading's units), and is shown as source when wider than the heading's narrower row; `state_row_count` counts them in the heading's units (an over-estimate by under `units` rows at worst, shaping corrects). While editing (C7): the caret line of a heading is built raw (`build_display_line_with(.., active)`) but its one segment is styled `Heading(level)` (level read from the inactive build), so it keeps the heading's size, weight, colour, spacing and rule and nothing moves when the caret enters; the `#`s are visible. Bold/italic/strike runs inside a heading take the heading's colour (`line_runs`). `RowCache::rebuild` ends with `sync_active_line`, so the caret's line is counted exactly (the cold estimate does not know the caret and counts a heading without its prefix, #74).

## GPUI/UI gotchas

- Reused `ElementId`s across panels break click dispatch — namespace per site (`"folder-{id}"`, `"search-result-{id}"`, `"backlink-{id}"`).
- Raw `window.on_mouse_event` listeners aren't hitbox-aware: Down/Move must bail on `window.has_active_dialog(cx)`.
- Dialog Enter dispatches to `.on_ok(...)`; set it to the same logic as the footer button. `AlertDialog` wires it already.
- Command palette: global `KeyBinding` + `cx.on_action` (element `.on_action` only sees the focused path); `CommandState` must be focused explicitly.
- Tab uses the `InsertTab` action in the `"TextEditor"` key context; test windows must register the binding.
- Icons need `.with_assets(gpui_kit::assets::Assets)`. Indent tree rows with `.ml(...)`, not padding.
- Updating another entity from a dialog callback: `entity.update(cx, |s, cx| s.method(window, cx))`, not `update_in`.
- Fonts (IBM Plex, OFL 1.1) are embedded via `include_bytes!` in `install_fonts`.

Nothing is computed unless asked, so normal frames cost nothing.

- **Float block (`::: float`, render only)**: `::: float [left|right] [N%]`, the float, `:::`, and the paragraphs after it are its text, with no wrapper or close marker for them. It is a `columns::Columns` with `kind: Aside`, `count: 2` and `tail: true`: the closing `:::` is `separators[0]` (rendered as nothing, like a frame line) and `end_line` is no marker line. `columns::derive(markers, line_count)` bounds the text at the next region's open marker (`tail_bound`) or the document's end; `Columns::cap_tail` then ends it at the first blank line outside code at least `TAIL_BASE + TAIL_PER_LINE * float_lines` lines after the float (16 + 4 per line), so a long note is not one region and no paragraph, table or callout is cut. `DocumentCache::cap_tails` runs after every edit (the cap reads line content, not just markers; `patch_columns` unions the old and new extents into the touched range), and after `recompute_all` once the line index exists. **Why a line budget, not the float's real height**: the extent being a function of source lines keeps the region's lines contiguous and `RowCache` independent per region (the first line holds the height, the rest 0); a layout-derived extent would make line ownership depend on the shaped rows. The cost is a gap under the text when a float is taller than its budget of lines (a very tall image over one-line paragraphs, with no later float of the other side to fill it). Layout is `shape_aside` unchanged: text beside the float at the channel width, cut at the float's bottom, then the whole width. **Stage 1, floats written among the text** (2026-11-21): a float block opening within `Columns::reach` (the same budget) of the last float's `:::` joins its region (up to `MAX_FLOATS` = 3 floats), so `count` is floats + 1 and `separators[k]` is float `k`'s `:::`, `opens[k]` its open marker; the lines of a later float block are in `column_lines(text)` (the hull) but not in `text_lines()`, which the layout walks. `shape_aside` shapes every float at its width up front (`FloatShape`) and puts each down when the text flow reaches the block it was written in (`Floats::place_before`, `Columns::float_anchor`; an aside's floats all at its top, as before): at `max(flow y, the side's free y)`, so on the opposite side it sits beside the text and on the same side it waits below the earlier float (CSS float behaviour). `Bands` is a list of `Placed{side, rows}` (floats on a side never overlap) instead of one occupied-rows value per side; `rows_from` is the next change of band, so a paragraph is cut where any float begins or ends. A float is also the end of the text above it only in the sense that the text keeps flowing; nothing is cleared. The widths of a region's floats come from one `aside_split`, so a side is as wide as its widest float. Not done: a float beyond reach or a fourth float starts its own region, and its text is cut off from the first's. **Step 3, built so far** (2026-11-21): *resize* is the divider grip (`Frame.buttons` is false for a tail: only grips, no `+`/unwrap); a drop calls `set_region_ratio`, which for a tail uses `columns::ops::float_markers` and rewrites only the float blocks' open markers (`edit_region` now replaces just the changed lines when the line count is the same), every float on that side taking the share, as for an aside. *Clear*: `::: clear` alone on a line (blank lines around it, like any marker) inside a float region's text is a hidden marker (`Columns::clears`, up to `MAX_CLEARS` = 3, only those inside the capped text; derived in `derive`'s last pass; the marker and its padding line are skipped by `text_lines`); `shape_aside` moves the flow to below every float placed so far (`Floats::clear_y`) when it reaches one. The flip/unwrap menu is still off for a tail region (`column_menu_state`). Not built: dragging a float to another paragraph. Guards: `columns::tests::a_float_block_*`, `document_cache::tests::float_blocks_stay_as_a_fresh_scan_finds_them_across_random_edits` (600 random edits against a fresh scan), `element::tests::a_float_block_flows_the_paragraphs_after_it`. Measured (release, 2026-11-21): `document_cache_new` typical/stress unchanged (+0.1%/+0.7%); the isolated `recompute_pass/columns` is ~+10% (0.3ms on the stress fixture, cold build only; `Columns` grew by `tail`/`tail_bound`); scrolling the float stress note p95 0.85ms.

- **Aside (floats with text flowing around them)**, merged from `feature/float-aside`, several floats added on `feature/multi-float-aside`: `::: aside [left|right] [N%]` opens it and is the first float; each further float (up to 3) starts at a `--- [left|right] [N%]` separator; the one plain `---` starts the text, which is last. Floats on one side stack down it with a row between and are as wide as the widest of them (`columns::side_shares`); `aside_split` places them and the text channel between, scaling the sides down together to keep `MIN_CHANNEL`. `shape_aside` computes bands per row (`Bands`: which rows each side is taken, including its air row), shapes each paragraph at the band of its first row and cuts it where a band changes, repeatedly. Grips are one per side (the left first): dragging one sets the share of every float on that side. `+` adds an empty float on the side the last one is not. The single-float description below still holds for one float: `::: aside [left|right] [N%]`, `---`, text, `:::`. It is a second `columns::Kind` of the same region: exactly two parts, the float (part 0) and the text (part 1), `percent = [share, 100 - share]` (share 10..=90, default right 40%). `columns::aside_split` places the float on its side and the channel beside it; the float is capped so the text keeps `MIN_CHANNEL` (560px, about 55 characters: measured, narrower channels leave rows 70-90% full and justifying them opens wide gaps; the requested share is kept in the file, only the drawn width shrinks); it stacks when the float would be under `MIN_FLOAT`. Hyphenation and optimal line breaking would help narrow measures further but need per-language support, so they are deferred. `region::shape_aside` shapes the float at its width, then the text line by line: beside the float (its rows plus one of air) at the channel width, below it at the whole width.   - **Syntax**: `::: columns` with an optional percent ratio that sums to 100 (`::: columns 60/40`, `20/50/30`; equal by default), content, `---` between columns, `:::` to close, each marker on its own line with a blank line before and after (without them another renderer reads a `:::` after a table row as a row, and a `---` under text as a heading underline). Inside a region `---` always means the next column; a rule inside a column is written `***`. Content has no prefix, so tables, images, lists, callouts and code stay normal top-level blocks (everything except another columns region). Rejected: `>` callout (a prefix on every line), HTML comments (invisible metadata), per-column fences (twice the markers), weights (`3/2`, means less to a reader). Elsewhere the region reads as plain text with a rule between the parts.

- **`jade-app` benchmarks**: `benches/editor.rs` (no feature needed) covers `DocumentCache` build, each classification pass (`Cache::recompute_*`), `record_edit`, `Fenwick` and `EditorBuffer` via `text_editor::bench_api` (thin wrappers; internals stay `pub(super)`). With `--features bench-support` (enables `gpui-kit/test-support`): `benches/layout.rs` times whole frames of the real app on GPUI's headless test platform (`headless::HeadlessApp`; layout and paint run, the GPU submit does not), and `benches/allocations.rs` (plain `main`, counting allocator) fails if an operation allocates more than its bound; GPUI itself allocates ~500KB per frame, so the frame bounds are regression ceilings, not claims it is small. Baseline on the stress fixture (release, one run): cold `DocumentCache::new` 26ms (one-time; line strides 3.0ms, then line roles 2.3ms, callouts 4.0ms, block contexts 7.1ms, tables 10ms), open note ~50ms (click, read, caches, first frame; one-time, not re-measured since the speedup), idle frame 0.39ms, sidebar drag step or sidebar toggle (whole-document `RowCache::rebuild` on the wrap-width change, run in the paint closure because layout is final there; the per-line counts that need no `Window` run on up to 8 threads above 20K lines, `pure_row_counts`) 5.7ms (was 13.4ms; live, `debug-socket`: 7.8-10.3ms paint, was 20-24ms; a 150KB note: 1.5ms), keystroke + frame 1.4ms (~1ms of it the `String::insert` memmove), scroll + frame 0.51ms, `record_edit` char 0.9µs, newline 1.2ms, char on a callout header 32µs; keystroke edit path 811 bytes in 23 allocations. Theme switch (`ThemeEngine::set`) + frame: 1.5ms on both the 150KB and the stress note (colors only, no cache rebuild), 936KB in 2354 allocations. A 150KB prefix: cold build 0.34ms, open 2.9ms, keystroke + frame 0.44ms. A headless frame cannot show GPU cost. Fixture: `crates/app/benches/fixtures/large_markdown_stress_test.md` (~11.8MB, seed `1337`, regenerate with `python3 crates/app/benches/fixtures/generate_stress_markdown.py`).
- **Images** (planned, render-only first; vault-local files only, no network): Obsidian's formats, `avif bmp gif jpeg jpg png svg webp`. GPUI's `img()` already decodes everything but AVIF (it compiles `image` with png/jpeg/webp/gif/bmp/tiff and `resvg` for SVG) but it decodes at full size (RGBA, 4 bytes a pixel) and every animation frame up front, so Jade needs its own off-thread decode, downscale and byte-budgeted cache in front of it. **Step 1 done (block foundation)**: `text_editor/image/embed.rs`; a whole-line vault-local embed (`jade_core::link_scan::parse_image_embed_line`: `![alt](p.png)` or `![[p.png|200]]`, Obsidian's extensions, no URLs) on an ordinary line (not code, table, callout, list or quote) and not under the cursor is one line of `PLACEHOLDER_ROWS` (6) rows: `build_display_lines` returns that many empty entries (the multi-entry path tables use), `estimate_row_count` returns the same height (a block must not take the 1-row fast path, `may_be_image` is the byte pre-check), and `paint_image_placeholder` draws a bordered box with the file name; the paint trace tags it `image`. The cursor on the line shows its source (one row). Cost on the stress fixture with an embed every 200 lines (1.6K blocks, headless): keystroke 1.80 to 1.85ms, scroll 0.79 to 0.81ms, sidebar resize 6.7 to 7.0ms (about 2%). **Step 3a done (real height)**: `text_editor/image/info.rs`. `Editor::set_image_context(root, note_id)` (called from `new_tab`) and `record_edit` ask `request_image_sizes` for embeds whose size is unknown; a background task reads each header (`imagesize`, no decode; `jade_core::image_file` resolves the path inside the vault only: the note's folder, then the root) and `apply_image_sizes` stores them in `DocumentCache::images` and calls `RowCache::invalidate(Invalidate::Width)` so the next paint rebuilds every count. A block is `rows_for` (displayed height + 4px, shrunk to the editor width and 1000px tall, `|200` sets the width) rows; unknown, missing or SVG (imagesize has no SVG) keeps the 6-row placeholder. Row counts now depend on `line_height` (in `RowParams`/`LineState::images`). A bare wikilink name found elsewhere in the vault (Obsidian's shortest-path rule) is not resolved yet, only paths. **Step 3b done (pixels)**: `text_editor/image/cache.rs`, an app-wide `Global` shared by all tabs and keyed by absolute path (`ImageInfo::path`). `paint_image` (in `paint_lines`) asks `image::Cache::lookup` for each block it paints, so only the viewport plus overscan decodes; a miss spawns `decode` on the background executor, scaled down (Triangle) to the drawn width in device pixels, never above the file's own, and `window.refresh()` runs when it lands. Until then (and for failures: SVG, AVIF, corrupt, over 64 MiB) the placeholder box is drawn. Decoded bytes are capped at 64 MiB; the least recently drawn goes first, never an image drawn this frame, and `begin_frame` frees evicted ones from the GPU atlas (`Window::drop_image`). A larger draw (window grown) re-decodes once and shows the smaller meanwhile. GIF draws its first frame. A bare name (`![[a.png]]`) is found anywhere in the vault, nearest the top first (`find_by_name`, hidden folders skipped, 200K-entry cap). Not done: a file changed on disk after its decode is not re-read until evicted; SVG (`resvg` is already in the tree) and AVIF. Measured in the release app on `vault/Image Test.md` (12 embeds incl. a 4000x3000 JPEG): steady-state scroll p50 0.24ms, p95 0.62ms; one 9.6ms frame when a large decode's pixels first reach the GPU; the first frame of a note open is 30ms (it was 39ms before images, so a cold-start cost, not new). AVIF, if wanted: `avif-decode` (pure Rust, rav1d) beats `image`'s `avif-native` (C libdav1d, fastest but a system library to package).
- **First frame of a note open is over budget**: 30ms in the release app on `vault/Image Test.md` (render 11ms + paint 19ms; 39ms on the same note before image support), measured 2026-11-20 with `jade-debug frames --raw`.
