# ARCHITECTURE.md

Non-obvious invariants, gotchas, and the Backlog. Not auto-loaded. The code is the source of truth for module structure — grep it.

## Invariants

- **Live Preview**: the cursor's line renders raw. A table renders entirely raw if the cursor is anywhere in it (`is_table_active`). Callouts are render-only (always expanded). List markers are *replaced* (`•`, `N. `), not just hidden. Lazy continuation is deliberately more lenient than CommonMark.
- **Cold build**: `DocumentCache::recompute_all` scans for newlines once (`line_strides`: SSE2 on x86_64, a word-at-a-time fallback elsewhere, no `memchr` per line, no pre-count) and the four passes read their lines back out of the strides, which then become the `line_index` Fenwick tree. Blank lines are decided from the first byte (`live_preview::is_blank`), table cell widths are computed without building cell strings, and a pipe row's delimiter is checked before its header is scanned. 81ms to 26ms on the stress fixture.
- **Text ownership**: note text exists once. `jade_core::Note` holds only id/path/title; the vault keeps the wikilink index and reads text from disk on demand (`read_note`, `save_note(&str)`, `search`). While a note is open its only copy is the editor buffer (`open_note` reads straight into it; autosave/flush write from the buffer's `&str`). No `.clone()`/`.to_string()` of the text anywhere (STYLE.md rule 14). Search reads files, so `JadeApp` caches results and recomputes only when `search_stale` is set by a mutation; searching runs on a background thread (`refresh_search` snapshots with `Vault::search_targets`, spawns, and drops results from superseded generations); never call `Vault::search` from `render`. Search sees disk, so unsaved edits show up after the 500ms autosave. The vault-open scan extracts wikilinks line by line (`link_targets_from_file`; a link never spans a line), and stores each note's distinct link targets only (`Box<[Box<str>]>`; the stress note's 27K links have 1 target), so scan peak is tiny, not a whole-file buffer (was a 14MiB peak; guard: `opening_a_vault_does_not_buffer_a_whole_note`).
- **Row heights**: `RowHeightCache` seeds non-table lines with an allocation-free over-estimate (`estimate_row_count`) and corrects to exact when painted, so total height starts slightly tall and settles while scrolling. Table rows always use the exact path. Validated against `exact_row_counts`. The first frame has no width yet (`render_params` falls back to `Pixels::MAX`, so every estimate is 1 row), and callout backgrounds are drawn before the lines from these heights; `LineLayout::verify_rows` therefore makes the visible window exact before the callout pass (guard: `first_paint_of_a_huge_note_needs_no_row_height_corrections`).
- **`DocumentCache` patching**: edits report a `TextEdit` to `Editor::record_edit`. A line-count change (Enter, joining lines, multi-line paste) resizes every per-line array and both Fenwick trees at one splice point (`resize_lines`, `Fenwick::resize`, `RowHeightCache::resize_for`), shifts stored line numbers of later tables/callouts, then runs the usual resumable walks. Undo/redo patch too: `EditorBuffer::undo`/`redo` return the `TextEdit` they applied (an undo entry is a delta). `classify_tables` (whole-document, with a per-line lookup) is now test-only: the oracle for the streaming `classify_table_list` production uses. A table's delimiter row needn't contain `|`, so `patch_tables` widens its window to fixpoint over adjacent tables and the header above. Validated by a randomized test (25 seeds) comparing every field, entering states included, against a freshly built cache.
- **Undo**: bursts of same-kind edits coalesce into one delta (`UndoEntry`: replaced range + removed text), so memory scales with edited text, not document size; stack capped at `UNDO_STACK_CAP` (100).
- **Tabs**: `JadeApp.tabs` + `active_tab`; each tab owns an `Editor` (cursor/scroll/undo survive switching), at most one tab per note (opening an open note switches to it). `open_note` = "Open" (replaces the active tab's note, or creates the first tab), `open_note_in_new_tab` appends. Autosave writes only `dirty` tabs (set by the delayed `Changed` event); `open_note`, vault renames and quit save *all* tabs unconditionally because `dirty` can lag a keystroke. Rename/delete go through `retarget_tabs`/`remove_tab`. Cost: ~33MB RSS per open stress-size note (3 tabs: 152 to 249MB); switching to one costs ~10ms over two frames (its row cache is rebuilt for the current width); the tab bar adds ~0.1ms per frame.
- **Status bar** (`status-bar` under the editor): word and character counts from `text_editor::doc_stats`, per-line `(words, chars)` patched with the same `EditPatch` as the caches (`Editor::record_edit`), totals kept as running sums. A word is a whitespace-separated token with a letter or digit (list markers, `---`, `|` don't count); characters are scalar values, spaces in, line breaks out. Cold count at note open: 8ms on the stress note (threaded over whole-line chunks above 1MB; 21ms single-threaded), 0.3ms on a 150KB note; per edit 0.17us (char) / 0.09ms (Enter); 8 bytes per line (~2.5MB on the stress note). The harness `app` query reports `words`/`chars`.
- **Themes** (`src/theme/`, format in `assets/themes/FORMAT.md`): `parse`/`loader`/`paths`/`builtin` are GPUI-free; `ThemeEngine` (a global installed in `run()`) holds the active `Palette`. Config dir: `JADE_CONFIG_DIR`, else `target/jade-dev` in debug builds, else the OS config dir + `jade/` (`theme/` and `config.toml` inside). Only `run()` reads the environment; tests pass dirs. Any bad theme logs to stderr and falls back to the built-in Jade Light, never a panic. Applied to gpui-component widgets (`apply.rs` builds a `ThemeConfig`; `MAPPING` is the single role-to-key table) and to `app.rs`, whose colors all come from `ThemeEngine::color`/`faded` (a test bans color literals there); the editor takes its colors from the palette too (`text_editor/colors.rs`: `InlineColors` for text runs, the palette itself for quads), and the same ban covers `element.rs`. Colors never affect layout, so a theme change repaints without touching `DocumentCache`/`RowHeightCache`. Tests/benches that render `JadeApp` must call `ThemeEngine::install(None, cx)` after `gpui_kit::init`. Hot reload (`watch.rs`): `run()` watches the config dir with `notify`; a 200ms poll task reloads once events go quiet. Only create/modify/remove events count: reading a theme raises access events and would loop. `ThemeEngine::reload` keeps the active theme on any error.
- **Window icon**: GPUI's `WindowOptions.icon` is X11-only, so on Wayland the icon comes from the `app_id` (`APP_ID` = `jade`, set in `run()`) matching `jade.desktop`. `packaging/` holds the entry and the 48px icon (copy of `assets/icons/jade-titlebar-48.png`); a packaged install puts them in `share/applications` and `share/icons/hicolor/48x48/apps`. Not implemented: the X11 icon (needs the `image` crate, which is not a dependency).
- **Links** (`jade_core::link_scan`, the one link grammar): leaf parsers (`parse_wikilink`, `parse_inline_link`, `parse_autolink`, `parse_bare_url`, `find_closing`) plus `scan_line`, which yields `Link { kind, span, text, dest, heading, alias }` as byte ranges into the line (no allocation, no text copy). `live_preview` calls the same leaf parsers; the vault's backlink index (`links.rs`) and, next, click-through, rename and backlink context call `scan_line`. `inline_start` skips the block prefix (blockquote, list marker, heading `#`) so a bullet `*` is not emphasis. Guarded by differential tests in `live_preview` (hand-written lines, 20K random token lines, the first 20K stress-fixture lines): everything rendered as a link is scanned, and a link rendering misses must lie inside bold/italic/strikethrough. **Known gaps**: Live Preview does not scan inside emphasis (`**[[a]]**` renders as plain bold, so it is not clickable, though it counts as a backlink); the vault scan is not fence-aware, so `[[x]]` inside a fenced code block still counts as a backlink; `[[#heading]]` (same-note anchor) is not a link yet. Behavior change from the old index: a wikilink in an inline code span or after `\` no longer counts, and `[[a|]]` / `[[ ]]` are not links. Cost: `Vault::open` on the stress note 27.4ms to 22.7ms (the byte lookup table `OPENS` skips plain text); `extract_wikilinks` (allocating helper, not hot) 15.3 to 18.5us typical, 209 to 243us worst case (the old `find("[[")` is vectorized; a `memchr` dependency would close it, not worth asking for).
- **Paint snapshot**: mouse closures share one `Rc<PaintSnapshot>` so hit-testing matches what was last painted, not the live document.
- **Autosave**: `open_note` subscribes to `EditorEvent::Changed`; `flush_editor` persists and drops the editor before `open_note`/renames.
- **Showcase fixture**: `vault/Markdown Showcase.md` (local, gitignored) must be updated in the same change that adds or changes a Live Preview construct.

## GPUI/UI gotchas

- Reused `ElementId`s across panels break click dispatch — namespace per site (`"folder-{id}"`, `"search-result-{id}"`, `"backlink-{id}"`).
- Raw `window.on_mouse_event` listeners aren't hitbox-aware: Down/Move must bail on `window.has_active_dialog(cx)`.
- Dialog Enter dispatches to `.on_ok(...)`; set it to the same logic as the footer button. `AlertDialog` wires it already.
- Command palette: global `KeyBinding` + `cx.on_action` (element `.on_action` only sees the focused path); `CommandState` must be focused explicitly.
- Tab uses the `InsertTab` action in the `"TextEditor"` key context; test windows must register the binding.
- Icons need `.with_assets(gpui_kit::assets::Assets)`. Indent tree rows with `.ml(...)`, not padding.
- Updating another entity from a dialog callback: `entity.update(cx, |s, cx| s.method(window, cx))`, not `update_in`.
- Fonts (IBM Plex, OFL 1.1) are embedded via `include_bytes!` in `install_fonts`.

## Headless UI tests

`cargo test -p jade-app -- --test-threads=1`.
- Clickable/findable elements need `.test_support()` plus `.id(...)`.
- Overlays open asynchronously: `cx.run_until_parked()` between separate `cx.update_window(...)` calls.
- Import gpui-kit items explicitly (a glob shadows `#[test]`).
- A `None`-context `KeyBinding` needs a focused element; clicking a non-`.track_focus()` div doesn't focus.
- `window.dispatch_keystroke` adds simulated text input for Enter/Tab/Space (`with_simulated_ime`), so an Enter through it inserts twice; the real Linux platform sends a bare key-down. Send Enter via `window.dispatch_event(PlatformInput::KeyDown(..))` when measuring it.
- `test_alloc.rs` (`#[cfg(test)]`): `reset()` rebases `peak` but must never zero `current`.

## Verifying perf/memory fixes

A fix isn't done until a test drives the real input path (`window.dispatch_keystroke`, `scroll_handle().set_offset` + `render_frame`), not just the underlying function. Calling `EditorBuffer::insert` directly hid a bug where `replace_text_in_range`'s `set_cursor` calls defeated undo coalescing (1.19GB retained over 150 keystrokes on the stress fixture, vs ~24MB fixed).
- Autosave is debounced (`AUTOSAVE_DEBOUNCE`, 500ms; flushed on note switch and app quit): a save copies the note, rescans wikilinks and rewrites the file. Paint/mouse closures read text and `DocumentCache` through the editor entity, never per-frame copies.
- `EditorBuffer` keeps `TEXT_GROWTH_CHUNK` spare capacity and grows in chunks, not by doubling (a cloned note has none; the first key used to retain ~11MB).
- Guards: `opening_a_huge_note_keeps_live_memory_bounded` (vault scan + open note <3.5x the note size; the vault keeps no text), `search_results_are_cached_until_something_changes`, `line_count_changing_edits_do_not_rebuild_the_document` (Enter/Backspace-join: bytes allocated), `first_keystroke_in_a_huge_file_does_not_reallocate_the_document`, `real_keystrokes_in_a_huge_file_do_not_churn_the_whole_document` (bytes allocated per key), `real_keystrokes_in_a_huge_file_keep_undo_memory_bounded`, `scrolling_through_a_huge_file_does_not_leak` (`app.rs`; heap flat across 200 scroll steps, RSS ~160MB flat in the headless harness).
- Real app: `JADE_MEMORY_LOG=1 cargo run -p jade-app --release --features debug-socket` logs RSS every 2s (`memory_probe.rs`).

## Debug harness

Lets a tool (Claude) drive and observe the live app. Code: `crates/debug-protocol` (wire types), `crates/debug-cli` (`jade-debug`), `crates/app/src/debug_server/`. Run `target/release/jade-debug help`; build with `cargo build --release -p jade-app --features debug-socket && cargo build --release -p jade-debug-cli`. The `debug-socket` feature is off by default: without it (outside tests) `debug_server_stub.rs` and `text_editor/paint_trace_stub.rs` provide same-named no-ops (`.debug_name(..)` returns the element unchanged), so the shipped binary has no input-injecting socket and `memory_probe` is not compiled; tests always use the real module. The default build does strictly less work, so a pass on the `debug-socket` build (what the harness measures) also holds for it; re-measure the default build only to diagnose a miss, and name the build when reporting numbers. Criterion benches run without the feature. Skill: `.claude/skills/jade-debug`.

- **Start/stop**: `jade-debug launch <vault>` starts the app on a *copy* of the vault (autosave would otherwise edit real notes) and waits until it is ready; `jade-debug quit` closes it (flushes the open note, removes the socket). By hand: `JADE_DEBUG_SOCKET=/path target/release/jade-app <abs vault>`. The window must be visible: an occluded window gets no frames, so nothing paints, input is not confirmed and `paint`/`frames` stay silent.
- **Wire**: newline-delimited JSON; every request has a `req`, answered by `{"kind":"response","req":N,"answer":{..}}`; events (`paint`, `memory`, `frames`, `input`) arrive as `{"kind":"event",..}` only after `subscribe`. Socket mode is 0600.
- **Commands**: `list_targets`; queries `memory|window_size|editor_state|app_state|frame_times|theme`; `set_theme` (this run only, `config.toml` untouched; the next reload returns to the configured theme); `read_editor_text`; input `type|key|mouse_move|mouse_down|mouse_up|click|drag|scroll` (`drag WHERE DX [DY] [STEPS]` presses, makes STEPS held-button moves, releases; `move --held` is one such move; GPUI starts a drag on the first moved event, so use STEPS >= 2 to see an effect; `app` reports the sidebar widths); `subscribe|unsubscribe|await`; `quit`. Mouse `at` is `{"point":{"x":..,"y":..}}` or `{"target":"note-Big"}`.
- **Ordering**: input is injected through `Window::dispatch_event`/`dispatch_keystroke` (real hit-testing, focus, bindings). Its reply is sent only after the window has painted the effect (`pump.rs`: two `on_next_frame` hops), and a client's reader does not read its next request until then, so scripts never act on a stale screen. No paint within 3s (hidden window, busy app) gives an error saying so; the input was still delivered. A waker-based pump hands commands to the main thread (no polling).
- **Targets** (`targets.rs`): `.debug_name("x")` / `.debug_name_with(|| format!(..).into())` wraps an element in `Named` (forwards to the inner element, no layout node) and records its bounds plus clip-visibility in prepaint; `JadeApp::render` clears the registry each frame, so it is the last painted frame. Add it as the *last* builder call. A click aims at the centre of the visible part; unknown, duplicate and clipped names are errors that say why. Named: `sidebar`, `sidebar-tab-vault|search`, `tab-bar`, `tab-{id}`, `tab-close-{id}`, `status-bar`, `grammar-check`, `toggle-sidebar`, `toggle-backlinks`, `backlinks-sidebar`, `sidebar-resize`, `backlinks-resize` (drag handles on the sidebars' inner edges), `new-note`, `new-folder`, `note-{id}`, `folder-{id}`, `search-result-{id}`, `backlink-{id}`, `editor-pane` (scroll container), `editor` (the text; click this to focus it), `search-input`, `rename-input`, `rename-folder-input`, `create-folder-input`, `confirm-|cancel-rename|rename-folder|create-folder`, `command-palette`, `settings-panel`, `theme-select`. **Name every new interactive widget.** Not nameable: gpui-kit alert-dialog buttons (drive with `enter`/`escape`) and popup/context-menu items (drive with the keyboard: the first `key down` highlights the first item, so Open in new tab is `down`, `down`, `enter`).
- **Feedback instead of silent `ok`**: `type` errors when nothing consumed the text (no text field focused; after opening a note the sidebar has focus, so click `editor` first). `read_editor_text` and `app_state` verify what input produced.
- **Frame times** (`frames.rs`): the editor canvas times `render_editor` (layout, measuring) and paint, per frame, into a fixed 240-slot ring (no allocation; ~0.7us/frame, nothing when the server is off). Jade's CPU work only, not GPU submit. `paint` frame numbers share the counter. Stress fixture while typing and scrolling: 0.96ms median, 1.62ms max; opening that note costs a one-time ~90ms first frame. Named elements add +0.04ms to a 1.85ms release frame (120 rows).
- **`paint` events** carry what the editor canvas painted (`text_editor/paint_trace.rs`: bands, visible lines y/rows/tag/preview, wrap width, verified window), only when a frame differs from the last, so a bug that fixes itself next frame is still seen; `consistent: false` means a callout band disagrees with its lines or painting corrected heights after the bands were placed.
- **Tests**: `debug_server::test_client::TestClient` + `open_app_with_debug_client`/`call_on_main`/`step` in `app.rs`. A test that talks to server threads needs `cx.executor().allow_parking()`; the headless window has no frame loop, so `call_on_main` calls `simulate_next_frame` to release painted-input replies and `step` renders a frame after each command.

## Backlog

Deliberately deferred — don't pick up without checking in (see `CLAUDE.md`).

- **Search on huge vaults**: search runs on a background thread, but its snapshot (`Vault::search_targets`, ~80ns/note on the UI thread) is O(notes): ~8ms at 100K notes, over budget past ~200K. Next step there: a cached `Arc` snapshot invalidated by note-set mutations, or an on-disk index.
- **Per-keystroke cost on the 320K-line stress fixture** (release, headless, so no GPU submit): a typed character is ~1.2ms edit + ~1.1ms render, Enter ~4ms + ~0.8ms, all under 16.66ms. ~1ms of the edit is `String::insert` memmoving the 11.8MB buffer; only a gap buffer/rope would remove it, at the cost of the contiguous `&str` that `text()` hands every consumer. The cache patch itself is ~0.1ms and allocates nothing (`callout_tail_scratch`, in-place `tables.splice`, `Table` stores no byte range: `DocumentCache::table_byte_range` derives it). Guard: `typing_a_character_in_a_huge_file_allocates_almost_nothing`.
- **Enter is O(lines after the edit), by design**: `resize_lines` memmoves the per-line `Vec`s and the Fenwick tree, 1.2ms mid-document and ~2ms at the start of the 320K-line fixture (release, cache patch only), within budget. Callout edits used to be O(lines after) too, because the per-line state held an absolute callout index; `CalloutState` is now two bits (the open callout is always the last one), `patch_callouts` splices a scratch list in place and shifts later callouts only when the line count changed (character on a callout header: 14.3ms to 32µs).
- **Memory on the stress fixture**: opening the note adds ~30MB live in the editor (`DocumentCache` 16.4MB, buffer 11.3MB, `RowHeightCache` 2.5MB), and nothing more: the vault holds no note text (see Text ownership below). Construction streams into the arrays, so peak equals live. Per-line `table_for_line`/`callout_for_line` arrays are gone (`table_index_at`/`callout_index_at` binary-search `tables`/`callouts`); fence/callout entering states are packed to 8 bytes (`pack_fence`, `CalloutState::pack`). Remaining per-line cost: `open_block_states` (16B + list nodes), `line_index` and row counts (8B each as `i64`). Allocations come mostly from table rows (`scan_row`).
- **`Vault::backlinks()`** rebuilds its whole map per call (worst measured ~0.44ms on 200 notes × 20k words, now that the index holds distinct targets only).
- **Live Preview**: full CommonMark emphasis; formatting visible on the active line; heading sizes (bold only); theme-driven colors (currently hardcoded `Hsla`).
- **Callouts**: fold interactivity (with task-checkbox toggling and WYSIWYG tables, a later "interactions" phase); nested callouts.
- **WYSIWYG table editing**: not designed.
- **Settings dialog**: only the theme chooser so far (a `Select` dropdown, target `theme-select`; its items are popup rows, so drive it with `down`/`enter`; `ThemeEngine::choose` switches and writes `theme` into `config.toml`, keeping other keys, never overwriting a file that doesn't parse). Text size and editor preferences to come. The theme list (built-ins plus up to 64 user files) is read once when the dialog opens.
- **`jade-app` benchmarks**: `benches/editor.rs` (no feature needed) covers `DocumentCache` build, each classification pass (`Cache::recompute_*`), `record_edit`, `Fenwick` and `EditorBuffer` via `text_editor::bench_api` (thin wrappers; internals stay `pub(super)`). With `--features bench-support` (enables `gpui-kit/test-support`): `benches/layout.rs` times whole frames of the real app on GPUI's headless test platform (`headless::HeadlessApp`; layout and paint run, the GPU submit does not), and `benches/allocations.rs` (plain `main`, counting allocator) fails if an operation allocates more than its bound; GPUI itself allocates ~500KB per frame, so the frame bounds are regression ceilings, not claims it is small. Baseline on the stress fixture (release, one run): cold `DocumentCache::new` 26ms (one-time; line strides 3.0ms, then line roles 2.3ms, callouts 4.0ms, block contexts 7.1ms, tables 10ms), open note ~50ms (click, read, caches, first frame; one-time, not re-measured since the speedup), idle frame 0.39ms, sidebar drag step (whole-document `RowHeightCache::rebuild` on the wrap-width change) 12ms (live, `debug-socket`: 10.7-16.4ms render+paint; table rows are ~60% of it; a 150KB note: 0.67ms), keystroke + frame 1.4ms (~1ms of it the `String::insert` memmove), scroll + frame 0.51ms, `record_edit` char 0.9µs, newline 1.2ms, char on a callout header 32µs; keystroke edit path 811 bytes in 23 allocations. Theme switch (`ThemeEngine::set`) + frame: 1.5ms on both the 150KB and the stress note (colors only, no cache rebuild), 936KB in 2354 allocations. A 150KB prefix: cold build 0.34ms, open 2.9ms, keystroke + frame 0.44ms. A headless frame cannot show GPU cost. Fixture: `crates/app/benches/fixtures/large_markdown_stress_test.md` (~11.8MB, seed `1337`, regenerate with `python3 crates/app/benches/fixtures/generate_stress_markdown.py`).
- **Grammar/spell checker**: its own feature. The status bar already shows its icon (`grammar-check`, a non-interactive placeholder) at the right end.
- **Tabs, later**: keyboard shortcuts (Ctrl+W close, Ctrl+Tab switch), drag-to-reorder tabs, restoring open tabs after a restart.
- **Permanently declined**: images, setext headings, indented code blocks, link reference definitions, raw HTML, hard/soft line-break distinction.
